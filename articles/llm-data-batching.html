LLM FROM SCRATCH · 08 · DATA · 22 MIN READ

The model can only learn from the examples you actually feed it.

Dataset preparation looks like plumbing until you realize that context length, batching, train/validation splits and data quality directly shape what the model can learn.

Lio Learning Path · Intermediate
Learning goal

Turn a token stream into training windows and batches, understand context length and leakage, and learn why data quality is part of model quality.

Begin with one long stream

After tokenization, a text corpus becomes integers:

[17, 42, 42, 91, 8, 203, 17, ...]

For a small experiment, this can be one contiguous tensor. In a larger system, data is usually stored in many tokenized shards or other efficient formats. The educational principle is the same: the model consumes token sequences, not raw files.

Split before sampling

We want a validation set the optimizer does not train on directly:

data = torch.tensor(encoded_text, dtype=torch.long)
n = int(0.9 * len(data))
train_data = data[:n]
val_data = data[n:]

The exact split strategy depends on the corpus. For real datasets, time order, documents and sources can make a random character-level split inappropriate.

Context length is a real limit

Let T be block size. Each training example contains T input tokens and T targets shifted by one.

ix = torch.randint(len(data) - T, (batch_size,))
x = torch.stack([data[i:i+T] for i in ix])
y = torch.stack([data[i+1:i+T+1] for i in ix])

The model can use at most T positions in one forward computation. A context window is therefore not “memory forever.” It is the amount of history available to the current computation.

Why longer context costs more

Attention compares positions with positions, producing a matrix with roughly T² entries per head. Increasing context length can therefore increase memory and compute rapidly.

Longer context is not automatically better. The model must have enough capacity and training data to learn useful long-range relationships, and the hardware must be able to afford them.

Why batches exist

A batch contains multiple windows that can be processed in parallel. Instead of launching a separate computation for every sequence, tensor libraries can use large matrix operations that modern accelerators handle efficiently.

x.shape == (B, T)
y.shape == (B, T)
embedding(x).shape == (B, T, C)

The batch dimension is not a new kind of information. It is parallelism: independent examples traveling through the same model.

Shuffle windows, not tokens

When sampling a simple contiguous corpus, choose random starting indices. The tokens inside each selected window must keep their original order.

def get_batch(split):
    source = train_data if split == "train" else val_data
    ix = torch.randint(len(source) - block_size, (batch_size,))
    x = torch.stack([source[i:i+block_size] for i in ix])
    y = torch.stack([source[i+1:i+block_size+1] for i in ix])
    return x.to(device), y.to(device)

The target is already inside the text

There is no separate “correct answer” file for ordinary next-token pretraining. The next token in the corpus is the target.

input:  the cat sat on th
target: he cat sat on the

The model sees the input sequence and learns a prediction at every position. This is why one corpus can generate an enormous number of training signals.

Data quality changes the learned distribution

Two identical Transformers trained on different corpora can behave very differently. Filtering, duplication, formatting, licensing, contamination and source balance all matter.

For our project, a small permissively usable corpus is enough. In a serious training pipeline, dataset construction becomes a major engineering and governance problem of its own.

Leakage can make evaluation lie

If near-duplicate documents appear in both training and validation sets, validation loss can look unusually good. The model may have seen essentially the same sequence during optimization.

For educational experiments, even a simple document-aware split is a useful improvement when your corpus contains repeated material.

Context length experiment

Train identical models with T=32 and T=128. Keep width and depth fixed. Record:

  • training speed
  • peak memory
  • validation loss
  • quality of long-range continuations

You are not searching for a universally correct context size. You are learning to see a systems trade-off.

When a dataset is too small

A tiny corpus can be excellent for learning because the model quickly overfits and produces visible changes. But the resulting model only learns that narrow distribution. A small Shakespeare-like corpus does not teach general world knowledge.

When more data does not fix the problem

If the tokenizer is broken, the causal mask leaks future information, the learning rate is unstable, or targets are misaligned, adding data can simply make the wrong computation run for longer.

Always validate the pipeline with tiny examples before scaling it.

Checkpoint

Explain why x=data[i:i+T] and y=data[i+1:i+T+1] are aligned, why the input shape is (B,T), and why attention makes long contexts expensive.

Data is not an accessory to the model. It defines the examples from which the optimizer is allowed to learn.
