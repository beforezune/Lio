The model only learns from the training examples you actually feed it.

Dataset preparation sounds like plumbing. In practice, it controls what the model can learn, how efficiently it learns, and what your loss numbers mean.

Start with a token stream

After tokenization, a text corpus becomes one long sequence of integer IDs. We split it into training and validation regions before sampling fixed-length context windows.

data = torch.tensor(encoded_text, dtype=torch.long)
n = int(0.9 * len(data))
train_data = data[:n]
val_data = data[n:]

Context length

If block size is T, every example contains T input tokens and T target tokens shifted by one. A longer context gives the model more history but increases attention memory roughly quadratically.

ix = torch.randint(len(data) - block_size, (batch_size,))
x = torch.stack([data[i:i+block_size] for i in ix])
y = torch.stack([data[i+1:i+block_size+1] for i in ix])

Why batches?

A batch contains multiple independent sequences processed in parallel. Matrix operations on a batch are far more efficient on modern accelerators than repeatedly processing one sequence.

With B sequences and T positions, the model input is (B,T) token IDs and the embedding output is (B,T,C).

Shuffle without destroying sequence order

We want different training windows across steps, but the tokens inside each window must retain their original order. Randomly choosing the starting index achieves this for a simple contiguous corpus.

Data quality matters

Deduplication, filtering, licensing, formatting and contamination checks are real parts of LLM development. A tiny educational model can use a small permissively usable corpus. A serious system needs a much more rigorous data pipeline.

Why train/validation splits matter

The validation set estimates performance on text the optimizer has not directly trained on. If the split leaks near-duplicates across both sets, the estimate can become misleadingly optimistic.

Batch construction in PyTorch

def get_batch(split):
    source = train_data if split == "train" else val_data
    ix = torch.randint(len(source) - block_size, (batch_size,))
    x = torch.stack([source[i:i+block_size] for i in ix])
    y = torch.stack([source[i+1:i+block_size+1] for i in ix])
    return x.to(device), y.to(device)

What context length really means

A context window is not “how much the model remembers forever.” It is the maximum number of positions included in the current forward computation. During generation, the model repeatedly appends tokens and uses a rolling context limited by the configured maximum.

Scaling the data pipeline

Large training systems shard data, pre-tokenize files, use memory-mapped formats, prefetch batches and distribute work across devices. The educational version should stay simple enough that you can inspect every batch.

Experiment

Train the same model with context lengths 32 and 128. Keep the model width fixed. Compare validation loss, memory use and training speed. You are learning a systems trade-off, not just a hyperparameter.

Data is part of the model

Two identical Transformer architectures trained on different corpora can behave very differently. Architecture determines the function family; data determines which patterns optimization is rewarded for learning.

If the model is the student, the dataset is the textbook, exercises and examples it sees every day.
