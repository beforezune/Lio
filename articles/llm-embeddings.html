LLM FROM SCRATCH · 03 · EMBEDDINGS · 20 MIN READ

The token is an ID. The embedding is where the geometry begins.

An LLM cannot do much with “cat” represented as the integer 417. It needs a vector that can be transformed, compared and updated by gradient descent.

Lio Learning Path · Beginner → Intermediate
Learning goal

Build the embedding stage, understand its tensor shapes, add positional information, and distinguish static token embeddings from contextual hidden states.

Why an integer is not enough

Suppose your vocabulary assigns cat → 17 and dog → 18. It would be meaningless to tell the neural network that dog is “one unit away” from cat. Token IDs are categorical labels, not measurements.

Neural networks work best when information can participate in continuous transformations. So we replace each integer with a vector.

The embedding table

Let V be the vocabulary size and C the model width. The token embedding matrix has shape (V,C). Every row belongs to one token.

token_embedding = nn.Embedding(vocab_size, n_embd)

idx = torch.tensor([[12, 45, 91]])
x = token_embedding(idx)
print(x.shape)  # (1, 3, n_embd)

If n_embd = 64, token 12 selects a 64-number row. A batch of three tokens therefore becomes three 64-dimensional vectors.

What training does to the table

At initialization, the rows are usually small random values. They become useful because the loss sends gradients backward through the network. If changing the representation of a token would improve prediction, gradient descent nudges that row.

This is an important distinction: embeddings are learned representations, not a hand-written semantic dictionary.

Why position must be added

Consider:

dog bites man
man bites dog

The same three content words occur in both sequences. If the model only saw token embeddings and had no position information, it would have no direct representation of order.

A simple GPT can learn a positional embedding for every allowed position:

self.token_embedding = nn.Embedding(V, C)
self.position_embedding = nn.Embedding(block_size, C)

positions = torch.arange(T, device=idx.device)
tok = self.token_embedding(idx)       # (B,T,C)
pos = self.position_embedding(positions) # (T,C)
x = tok + pos                         # (B,T,C)

Broadcasting adds the same position vector across the batch. The resulting representation carries both token identity and position.

Why addition rather than concatenation?

Concatenation would increase the width of the representation. Addition preserves C. It also places content and position into a shared feature space that later layers can transform together.

This is one design choice, not a law of nature. Transformer families use different positional mechanisms, including learned positions, sinusoidal encodings and rotary position representations.

The shape language of our model

From this point on, keep three symbols in your head:

  • B = batch size
  • T = number of token positions
  • C = embedding/model width

The token IDs have shape (B,T). After embedding, the hidden state has shape (B,T,C). The model will preserve this main shape through every Transformer block.

Embedding is lookup, not matrix multiplication

An embedding lookup can be viewed as selecting rows from a matrix. It is mathematically related to multiplying a one-hot vector by the embedding matrix, but implementations avoid constructing those huge one-hot vectors.

# Conceptually
one_hot(token_id) @ embedding_matrix

# Practically
embedding(token_id)

The practical version is faster and communicates the intention more clearly.

Static versus contextual representations

The embedding for token bank is the same row whenever the token ID is the same. But later, after attention, the hidden state for bank can differ depending on surrounding tokens.

river bank
bank account

The embedding is the starting point. The Transformer computes a contextual representation by mixing information from the sequence.

Inspect the actual tensor

with torch.no_grad():
    w = model.token_embedding.weight
    print("shape:", w.shape)
    print("mean:", w.mean().item())
    print("std:", w.std().item())
    print("first row:", w[0][:8])

During learning, inspection is not a distraction. Print shapes at every boundary. Look at parameter statistics before and after training. When a model is broken, tensors usually tell you where the story stopped making sense.

Initialization and symmetry

If every token started with exactly the same vector, the network would have little information with which to distinguish them. Random initialization breaks that symmetry. Optimization then reshapes the space according to the training objective.

A useful experiment

Train the same tiny model twice: once with positional embeddings and once with positions disabled. Use a dataset where order matters. Compare validation loss and generated text.

The point is not to prove that one positional method always wins. The point is to feel why order must enter the computation somehow.

Checkpoint

Given V=10,000, B=4, T=32, C=128, the embedding matrix is (10000,128), the input IDs are (4,32), and the embedded batch is (4,32,128). If you can reason about these shapes, you are ready for attention.

An embedding gives every token a learned starting coordinate. Attention turns those coordinates into context.
