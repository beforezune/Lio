LLM FROM SCRATCH · 03 · EMBEDDINGS · 17 MIN READ

How an LLM turns a token ID into a vector it can actually compute with.

The token “cat” starts life as an integer. The embedding layer turns that integer into a learned point in a high-dimensional space.

Lio Learning Path · Beginner → Intermediate

The lookup table

An embedding matrix is simply a trainable matrix with one row per vocabulary item. If the vocabulary has V tokens and the model dimension is C, the matrix has shape (V, C).

embedding = nn.Embedding(vocab_size, n_embd)

idx = torch.tensor([[12, 45, 91]])
x = embedding(idx)
print(x.shape)  # (1, 3, n_embd)

Conceptually, the operation is a lookup. Token 12 selects row 12. Token 45 selects row 45. Nothing about this first step “understands” language. The rows become useful because gradient descent changes them during training.

Why vectors?

Vectors give the network a continuous space in which transformations can happen. A scalar token ID cannot express useful relationships: the fact that token 100 is numerically close to token 101 should not mean those tokens are semantically close.

In an embedding space, however, the training process can discover directions and neighborhoods that help predict text. Similar contexts can push representations into useful configurations.

Token embeddings are not enough

Consider the sequence “dog bites man” and “man bites dog.” The same token vectors appear in both. The model therefore needs information about position and context. Position tells the network where a token occurs; attention later lets each token incorporate information from other tokens.

Position information

A tiny GPT can use a learned positional embedding table:

token_emb = self.token_embedding(idx)
positions = torch.arange(T, device=idx.device)
pos_emb = self.position_embedding(positions)
x = token_emb + pos_emb

Now x has shape (B, T, C): batch, sequence length, channels. This three-letter shape will appear everywhere in the implementation.

Why addition?

Adding token and position vectors keeps the representation width fixed. The model receives both kinds of information in the same C-dimensional space and learns how to use the mixture.

Initialization matters

Embeddings begin with small random values. If all rows started identical, gradient updates would have difficulty breaking the symmetry. Random initialization gives different tokens distinct starting points.

Inspecting embeddings

with torch.no_grad():
    v = model.token_embedding.weight
    print(v.mean().item())
    print(v.std().item())
    print(v.shape)

For learning, inspection is valuable. Print shapes. Check means and standard deviations. Take a few vectors and compare them before and after training. A model stops feeling abstract when you can see the tensors changing.

Learning checkpoint

Be able to answer: Why is an embedding a matrix? Why does a token ID not itself contain meaning? Why do we need position information?

From lookup table to contextual representation

An embedding is static for a given token. After attention and feed-forward layers, the hidden state is contextual. The representation of “bank” in “river bank” can differ from “bank account” because the surrounding tokens change the computation.

The embedding gives a token a starting coordinate. The Transformer turns that coordinate into a context-dependent representation.
