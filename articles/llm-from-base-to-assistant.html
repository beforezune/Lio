Pretraining teaches a model to continue text. A useful assistant needs additional training, evaluation, product constraints and careful deployment.

Base model versus assistant

A base causal language model is optimized to predict the next token in text. If you prompt it with a fragment of an article, it may continue the article. That does not mean it has been trained to follow arbitrary user instructions reliably.

An assistant-style system typically adds stages such as supervised instruction tuning and preference-based optimization, plus inference-time system instructions, safety mechanisms and tool integrations.

Instruction tuning

A simple supervised example contains an instruction and a desired response. Training then increases the probability of the target response given the input conversation. The underlying next-token objective remains; the data distribution has changed.

Preference optimization

Human preference data can provide a signal about which candidate responses are more useful. Modern alignment methods vary widely, and the engineering details matter. The educational point is that “chat behavior” is not a property that appears automatically from the Transformer architecture.

Evaluation

Evaluate separate capabilities instead of relying on one score. Useful dimensions include next-token loss, factual accuracy, instruction following, coding correctness, robustness to ambiguity, refusal behavior where appropriate, latency and cost.

A tiny model should be judged against its intended scope. A character-level Shakespeare model is successful if it learns its narrow distribution; it is not evidence that it can answer general questions.

Common misconceptions

“The model stores every sentence it saw.”

Parameters encode statistical structure learned from data. Memorization can occur, especially for repeated or rare examples, but the architecture is not a literal text database.

“More parameters always means better.”

Scale interacts with data quality, optimization, architecture, compute and evaluation. Bigger is not a substitute for sound experimental design.

“Attention is the whole LLM.”

Attention is central, but the model also depends on embeddings, MLPs, normalization, residual pathways, optimization, data and decoding.

“A good loss proves the model is useful.”

Loss measures the training objective. Product usefulness requires additional evaluation. A model can reduce perplexity while still producing poor answers for a particular task.

Final project

Train a tiny character-level GPT. Then replace the character tokenizer with a simple subword tokenizer, add multi-head attention, compare context lengths, plot train/validation loss, and test three sampling temperatures. Write down what changed and why.

The real achievement

If you completed this path, you can now read a GPT-style implementation and identify the major transformations: token IDs enter embeddings; embeddings become contextual through repeated attention and MLP blocks; a vocabulary projection produces logits; cross-entropy trains the network; decoding turns logits into text.

That mental model scales. Commercial models add many optimizations, architectural choices, distributed-training systems and post-training stages, but the core computational story remains recognizable.

You do not understand an LLM because you can name its parts. You understand it when you can trace one token through the entire system.

Keep building

The next useful step is not another diagram. Change the code. Remove a head. Halve the context. Train longer. Inspect a batch. Break the mask and watch what happens. Learning accelerates when the model becomes an object you can experiment on.
