LLM FROM SCRATCH · 01 · ROADMAP · 18 MIN READ

Build an LLM from scratch. First, see the whole machine.

Before we write attention code, we need a map. By the end of this series you will have traced one piece of text all the way from characters to tokens, vectors, attention, gradients and generated text.

Lio Learning Path · Beginner → Intermediate
The promise

You will not memorize ten Transformer terms. You will build a small GPT-style language model and understand why each component exists.

Start with one deceptively simple question

Suppose I give a model the text the cat sat on the. What does it actually do when it predicts mat?

It does not search a sentence database. It does not look up the answer in a dictionary. It converts the text into numbers, transforms those numbers through a stack of learned functions, produces one score for every possible next token, and learns by making those scores better over millions of examples.

That is the machine we are going to open.

The complete computational story

For this series, our target is a decoder-only autoregressive Transformer in the GPT family. The vocabulary has V possible tokens, the context has T positions, and the model represents each position with C numbers.

text
  ↓
tokenizer
  ↓
(B, T) token IDs
  ↓
embedding + position
  ↓
(B, T, C) hidden states
  ↓
Transformer block × N
  ↓
(B, T, C)
  ↓
linear language-model head
  ↓
(B, T, V) logits
  ↓
softmax / sampling
  ↓
next token

During training, the arrow continues in a loop:

logits → cross-entropy loss → gradients → optimizer update → new weights

Why the order matters

There is a temptation to start with “what is attention?” because attention is the famous part. That is backwards for learning. Attention operates on vectors, so first we need tokens and embeddings. A useful Transformer block needs residual streams and normalization. A model without a training objective has nothing to optimize. A trained model without decoding cannot produce a continuation.

Each lesson therefore builds on the previous one. We will keep the same small codebase rather than writing isolated toy snippets that never meet each other.

Lesson 1 — Tokenization

The computer cannot feed a sentence directly into a matrix multiplication. Tokenization creates a finite alphabet for the model: token IDs. We will begin with characters because they make every transformation visible, then discuss why real systems use subword or byte-level schemes.

Lesson 2 — Embeddings

An integer such as 417 is an index, not a useful representation. An embedding table turns each ID into a learned vector. We will also add positional information so the model can distinguish dog bites man from man bites dog.

Lesson 3 — Self-attention

Now the vectors need a way to exchange information. Queries, keys and values create a differentiable routing mechanism. The causal mask is crucial: when predicting position t, the model may use the past but not the future.

Lesson 4 — Multi-head attention

One attention pattern is restrictive. Multiple heads let different learned projections route different kinds of information in parallel. We will pay close attention to tensor reshaping because shape mistakes are among the most useful bugs to encounter while learning.

Lesson 5 — The Transformer block

Attention alone is not GPT. We will combine attention with a position-wise MLP, LayerNorm and residual connections, then stack blocks into a complete decoder.

Lesson 6 — Training

The model now exists, but it knows nothing. We will follow one batch through the forward pass, cross-entropy, backpropagation and AdamW. We will compare training and validation loss and learn what an actual optimization curve tells us.

Lesson 7 — Data and batching

The model only learns from the examples we present. We will build fixed-length context windows, batches and train/validation splits, then investigate how context length affects memory and learning.

Lesson 8 — Generation

Training predicts distributions; generation chooses tokens. We will implement greedy decoding, temperature and top-k sampling, and see why a tiny change in decoding can completely change a continuation.

Lesson 9 — Base model to assistant

Next-token prediction is not the same as instruction following. We will separate pretraining from post-training, discuss supervised instruction tuning and evaluation, and be precise about what a tiny educational model can and cannot demonstrate.

The vocabulary we will keep returning to

Token

A discrete ID representing a piece of text.

Embedding

A learned vector associated with a token.

Hidden state

A contextual vector produced inside the Transformer.

Logit

An unnormalized score for a possible next token.

Parameter

A learned number changed by optimization.

Loss

A scalar measuring how poorly predictions match targets.

What “from scratch” means here

We will use PyTorch for tensors, automatic differentiation and hardware acceleration. We will not call a ready-made language-model class that hides the architecture. The framework is our calculator; the educational work is writing and inspecting the calculation.

We are deliberately building a tiny model. That is a feature, not an apology. A model small enough to train on modest hardware gives you the freedom to print tensors, break masks, change dimensions and rerun experiments.

Before you continue

You should be able to explain this sentence: “An autoregressive language model maps a token context to a probability distribution over the next token.” If that sentence is clear, the rest of the series has somewhere to attach.

Your final experiment

At the end, do not stop when the model generates vaguely plausible text. Change something. Remove an attention head. Shorten the context. Increase the vocabulary. Change temperature. Plot train and validation loss. The goal is to turn the model from a black box into an experimental object.

The point of building a tiny LLM is not to compete with a giant model. It is to make every hidden step visible.
