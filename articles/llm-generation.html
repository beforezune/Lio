The model predicts a distribution. Generation decides what happens next.

Training teaches the model to assign probabilities to possible continuations. Inference repeatedly turns those probabilities into tokens, feeding each choice back into the model.

Lio Learning Path · Intermediate
Learning goal

Implement autoregressive generation and understand greedy decoding, temperature, top-k, top-p, stopping rules and why inference can behave very differently from training.

One token at a time

Suppose the prompt has already been tokenized. The model produces logits for every position, but during generation we only care about the final position:

logits = model(context)
next_logits = logits[:, -1, :]

Those final logits score possible next tokens. We convert them into a distribution:

probs = F.softmax(next_logits, dim=-1)

Then we choose one token, append it to the context and repeat.

The complete loop

context = prompt
for step in range(max_new_tokens):
    window = context[:, -block_size:]
    logits = model(window)
    next_logits = logits[:, -1, :]
    probs = F.softmax(next_logits, dim=-1)
    next_token = torch.multinomial(probs, 1)
    context = torch.cat((context, next_token), dim=1)

This is autoregressive generation. The model's previous output becomes part of its next input.

Greedy decoding

The simplest decoder chooses the highest-probability token:

next_token = torch.argmax(
    next_logits, dim=-1, keepdim=True
)

It is deterministic and easy to reason about. But always taking the local maximum can produce repetitive or dull sequences. A language model's probability distribution often contains several plausible continuations.

Temperature changes the distribution

Temperature rescales logits before softmax:

scaled_logits = next_logits / temperature
probs = F.softmax(scaled_logits, dim=-1)

At a lower temperature, differences between logits become more pronounced and the distribution becomes sharper. At a higher temperature, probabilities become flatter.

Temperature does not create knowledge. It changes how aggressively we sample from the model's existing uncertainty.

Top-k keeps the strongest candidates

Instead of sampling from the entire vocabulary, keep only the k highest logits:

values, indices = torch.topk(next_logits, k)
filtered = torch.full_like(next_logits, float('-inf'))
filtered.scatter_(1, indices, values)
probs = F.softmax(filtered, dim=-1)

This removes the long tail of extremely unlikely tokens. It is easy to implement and easy to visualize.

Top-p adapts to the distribution

Nucleus sampling chooses the smallest candidate set whose cumulative probability reaches a threshold p. Unlike top-k, the number of candidates changes with the shape of the distribution.

If the model is very confident, the nucleus may contain only a few tokens. If uncertainty is spread across many tokens, it can contain more.

Why one bad choice can snowball

During training, the model usually receives real prefixes from the dataset. During generation, it receives its own previous choices. A strange token can push the context into a region the model rarely saw, making later predictions less reliable.

This is one reason generated text is a sequential process rather than a collection of independent predictions.

Training and inference are different modes

During evaluation, use model.eval() so layers such as dropout behave correctly. Disable gradient tracking when generating:

model.eval()
with torch.no_grad():
    # generation loop

Generation does not need gradients, so tracking them wastes memory and compute.

Stopping matters

A decoder needs a stopping rule. Common choices include an end-of-sequence token, a maximum number of generated tokens, or an application-specific stop sequence.

Our tiny character model can simply stop after a fixed number of tokens. A conversational application needs more careful control.

The hidden cost of recomputation

The simple educational loop feeds the growing context back through the Transformer each time. That means earlier attention keys and values are recomputed repeatedly.

Production decoders use a key-value cache: once a previous token's keys and values have been calculated, later steps can reuse them. The algorithm is still autoregressive, but the implementation avoids redundant work.

A decoding experiment worth doing

Choose one prompt and generate five samples at temperatures 0.5, 0.8 and 1.2. Compare:

  • repetition
  • diversity
  • coherence
  • failure modes

Do not judge a sampling method from one lucky sample. Random generation needs repeated trials.

Training learns the shape of the probability distribution. Decoding chooses a path through it.
