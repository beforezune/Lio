LLM FROM SCRATCH · 05 · MULTI-HEAD · 21 MIN READ

One attention head sees one learned view. Multi-head attention gives the model several.

The trick is simple: project the same hidden states into several smaller spaces, run attention in parallel, concatenate the results, then mix them again.

Lio Learning Path · Intermediate
Learning goal

Understand why heads are split, derive the tensor reshapes, implement multi-head causal attention, and learn how to use optimized attention without losing the underlying mental model.

Why not one giant head?

Imagine a model with width C=256. One attention mechanism could compare 256-dimensional queries and keys. It would have a lot of capacity, but it would have to express every useful routing pattern through one projection.

Instead, suppose we use eight heads of width 32. Each head sees a learned projection of the same input. The heads can discover different patterns because their parameters are different.

C = 256
n_head = 8
head_size = C // n_head  # 32

Do not turn this into a rigid story that head 1 “does syntax” and head 2 “does names.” Training does not assign jobs in advance. Multiple heads simply give the network multiple learned routing channels.

Start from the shape

Before attention, our hidden state is:

x: (B, T, C)

We project Q, K and V. If we then split the final dimension into heads, we get:

(B, T, C)
→ (B, T, H, D)
→ (B, H, T, D)

Here H is number of heads and D=C/H is the head width. The transpose puts the head dimension before sequence length so matrix multiplication can run independently for each head.

Build the projections

q = self.query(x)
k = self.key(x)
v = self.value(x)

q = q.view(B, T, H, D).transpose(1, 2)
k = k.view(B, T, H, D).transpose(1, 2)
v = v.view(B, T, H, D).transpose(1, 2)

Now:

q, k, v: (B, H, T, D)

Attention happens per head

scores = q @ k.transpose(-2, -1)
# (B,H,T,D) @ (B,H,D,T)
# → (B,H,T,T)

scores = scores * D ** -0.5
scores = scores.masked_fill(mask == 0, float('-inf'))
weights = F.softmax(scores, dim=-1)
out = weights @ v
# (B,H,T,T) @ (B,H,T,D)
# → (B,H,T,D)

The important insight is that the computation is exactly the same attention equation from the previous lesson. We are simply running it H times in parallel.

Put the heads back together

After attention, transpose back and reshape:

out = out.transpose(1, 2).contiguous()
out = out.view(B, T, C)
out = self.proj(out)

The concatenation restores the original width. The final projection mixes information across heads and produces the block's attention update.

A complete implementation

class MultiHeadAttention(nn.Module):
    def __init__(self, n_embd, n_head, block_size, dropout=0.0):
        super().__init__()
        assert n_embd % n_head == 0
        head_size = n_embd // n_head
        self.n_head = n_head
        self.head_size = head_size
        self.query = nn.Linear(n_embd, n_embd, bias=False)
        self.key = nn.Linear(n_embd, n_embd, bias=False)
        self.value = nn.Linear(n_embd, n_embd, bias=False)
        self.proj = nn.Linear(n_embd, n_embd)
        self.dropout = nn.Dropout(dropout)
        self.register_buffer("mask", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape
        q = self.query(x).view(B,T,self.n_head,self.head_size).transpose(1,2)
        k = self.key(x).view(B,T,self.n_head,self.head_size).transpose(1,2)
        v = self.value(x).view(B,T,self.n_head,self.head_size).transpose(1,2)
        scores = q @ k.transpose(-2,-1) * self.head_size ** -0.5
        scores = scores.masked_fill(self.mask[:T,:T] == 0, float('-inf'))
        weights = F.softmax(scores, dim=-1)
        weights = self.dropout(weights)
        out = weights @ v
        out = out.transpose(1,2).contiguous().view(B,T,C)
        return self.proj(out)

Why the final projection matters

Concatenation places each head's output next to the others. The projection learns how to combine those features. It is another trainable transformation, not just a formatting step.

Dropout belongs to training

Dropout randomly removes some activations during training to reduce overfitting. At evaluation time, dropout is disabled. For a tiny educational model, start with dropout=0 so you can isolate the architecture, then introduce dropout as an experiment.

Optimized attention

Once the concept is understood, production code should not necessarily materialize every intermediate tensor. PyTorch exposes optimized scaled dot-product attention:

out = F.scaled_dot_product_attention(
    q, k, v,
    attn_mask=None,
    dropout_p=dropout if self.training else 0.0,
    is_causal=True,
)

Optimized kernels can reduce memory movement and exploit hardware more efficiently. The abstraction does not invalidate the educational implementation; it packages the same mathematical operation more efficiently.

What to measure

Try the same tiny model with 1, 2, 4 and 8 heads while keeping total width constant. Compare validation loss and training speed. You are testing whether dividing capacity into more routing subspaces helps this particular model and dataset.

Also inspect the attention weights. Do not overinterpret individual heads, but use them to understand the mechanics.

Shape checkpoint

With B=4,T=32,C=128,H=4, each head has D=32. Q/K/V are (4,4,32,32) after splitting, attention scores are (4,4,32,32), and the combined output returns to (4,32,128).

Multi-head attention does not add a new kind of mathematics. It gives the same attention operation several learned spaces in which to work.
