Why one attention head is not enough.

Multi-head attention lets the model learn several information-routing patterns in parallel, then recombine them into one representation.

Lio Learning Path · Intermediate

Split the representation

Suppose the model width is C = 256 and we use 8 heads. A common design gives each head a width of 32. Instead of asking one 256-dimensional attention mechanism to do everything, we create several smaller projections.

head_size = n_embd // n_head
# q, k, v per head: (B, T, head_size)

Each head gets its own learned projections. Because the projections differ, heads can learn different useful comparisons.

The implementation pattern

q = self.query(x).view(B, T, n_head, head_size).transpose(1, 2)
k = self.key(x).view(B, T, n_head, head_size).transpose(1, 2)
v = self.value(x).view(B, T, n_head, head_size).transpose(1, 2)

scores = q @ k.transpose(-2, -1)
scores = scores * head_size ** -0.5
scores = scores.masked_fill(mask == 0, float('-inf'))
weights = F.softmax(scores, dim=-1)
out = weights @ v
out = out.transpose(1, 2).contiguous().view(B, T, C)
return self.proj(out)

Read the shapes carefully

Before splitting, x is (B,T,C). After splitting and transposing, queries become (B,H,T,D), where H is the number of heads and D is the per-head dimension. Matrix multiplication then produces (B,H,T,T) attention scores.

Concatenate, then mix

The outputs of all heads are concatenated back to width C. A final linear projection mixes information across heads:

combined = head_outputs.reshape(B, T, C)
out = self.proj(combined)

That projection matters. Without it, each head would remain isolated after concatenation. The output matrix learns how to recombine the features.

Why multiple heads can help

A sequence contains many simultaneous relationships. One pattern might care about a nearby syntactic dependency. Another may track a repeated name. Another might behave more like local context. The model is not explicitly assigned these jobs; gradient descent discovers whatever routing patterns improve the objective.

Important distinction

Do not memorize the slogan “each head learns one linguistic feature” as a law. Head behavior is learned, distributed and often messy. Multi-head attention gives the network capacity for multiple routing patterns; it does not prescribe their interpretation.

Dropout

During training, attention weights or projection outputs may use dropout as a regularizer. At inference, dropout is disabled. For a tiny educational model, you can start with zero dropout to reduce moving parts, then add it as an experiment.

Using PyTorch's fused attention

For performance, PyTorch provides optimized scaled dot-product attention. The educational implementation above is valuable because it exposes the computation. Production training generally benefits from optimized kernels and memory-aware implementations.

out = F.scaled_dot_product_attention(
    q, k, v, is_causal=True
)

The abstraction is still implementing the same conceptual operation: scaled query-key matching, causal masking, softmax, and weighted value aggregation.
