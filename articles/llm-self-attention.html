LLM FROM SCRATCH · 04 · SELF-ATTENTION · 24 MIN READ

Self-attention is how a token asks the rest of the sentence for context.

The surprising part of a Transformer is not that it has vectors. It is that every position can learn where to look, how strongly to look, and what information to bring back.

Lio Learning Path · Intermediate
Learning goal

Derive scaled dot-product attention, understand queries, keys and values, implement a causal attention head, and reason about every tensor shape.

Start with a problem

Take the sentence: The animal didn't cross the road because it was tired. What should “it” refer to?

A token representation that only contains its own embedding cannot answer. It needs information from other positions. Attention provides a differentiable way to retrieve that information.

The three projections

Start with hidden states x of shape (B,T,C). We create three learned projections:

q = Wq(x)
k = Wk(x)
v = Wv(x)

Queries describe what a position is looking for. Keys describe what each position can be matched on. Values contain the information that gets mixed into the output.

These are useful mental models, not literal human-readable labels. The network learns the matrices; it is not explicitly told to put “questions” in Q and “answers” in V.

Step 1: compare queries with keys

For one head with dimension D, each query is compared with every key using a dot product:

scores = q @ k.transpose(-2, -1)

If q is (B,T,D), then the score matrix is (B,T,T). The last two dimensions say: for every query position, produce one score for every key position.

Step 2: scale the scores

We divide by the square root of the key dimension:

scores = scores / math.sqrt(D)

Why? Dot products tend to grow in magnitude as dimensionality increases. Very large logits can make softmax extremely sharp, which can produce poor gradients. Scaling keeps the values in a more useful range.

Step 3: enforce causality

GPT-style language modeling has a strict information rule: position t may use positions at or before t, but it cannot see future tokens.

mask = torch.tril(torch.ones(T, T, device=x.device))
scores = scores.masked_fill(mask == 0, float('-inf'))

After softmax, the masked entries receive probability zero.

This is more than an implementation detail. Without the mask, training would leak the answer into the input. The model could appear to learn while solving an easier problem than the one generation requires.

Step 4: turn scores into weights

weights = F.softmax(scores, dim=-1)

Softmax converts each row into non-negative weights that sum to one. Now each token has a learned distribution over the positions it is allowed to read.

Step 5: mix the values

out = weights @ v

The output is a weighted average of value vectors. Attention is therefore a routing mechanism: the score computation decides where to read; the weighted sum decides what information arrives.

The full equation

Attention(Q,K,V) = softmax(QKᵀ / √D) V

Read it left to right: compare Q and K, scale the comparison, normalize it into weights, then use those weights to mix V.

Implement one head

class Head(nn.Module):
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.key = nn.Linear(n_embd, head_size, bias=False)
        self.query = nn.Linear(n_embd, head_size, bias=False)
        self.value = nn.Linear(n_embd, head_size, bias=False)
        self.register_buffer(
            "tril", torch.tril(torch.ones(block_size, block_size))
        )

    def forward(self, x):
        B, T, C = x.shape
        k = self.key(x)                  # (B,T,D)
        q = self.query(x)                # (B,T,D)
        v = self.value(x)                # (B,T,D)
        scores = q @ k.transpose(-2,-1)  # (B,T,T)
        scores = scores * C ** -0.5
        scores = scores.masked_fill(
            self.tril[:T,:T] == 0, float('-inf')
        )
        weights = F.softmax(scores, dim=-1)
        return weights @ v

One small naming improvement is worth making in a real implementation: use head_size rather than C for the scale because the score dimension is the head dimension. The correct factor is head_size ** -0.5.

Inspect the attention matrix

For a sequence of four tokens, the causal weight matrix has this structural form:

token 0: [1, 0, 0, 0]
token 1: [•,  •, 0, 0]
token 2: [•,  •, •, 0]
token 3: [•,  •, •, •]

The dots are learned probabilities. The zeros are enforced by the mask.

Plotting this matrix for a tiny model is one of the best educational experiments you can do. You can literally see which positions are allowed to communicate.

What attention is not

Attention weights are not guaranteed to be explanations of a model's reasoning. A high weight means the computation routes value information strongly through that connection. Human interpretation requires additional evidence.

Likewise, attention is not a literal database search. It computes weighted combinations dynamically for each input.

The quadratic cost

The score matrix has T × T entries. If you double the context length, the number of pairwise attention scores grows by about four times. This quadratic relationship is a major reason long-context efficiency is difficult.

A failure experiment

Remove the causal mask and train a tiny model. Its loss may fall surprisingly quickly. Then try generation. You have created a mismatch: training allowed information that generation does not have.

This is a valuable lesson in machine learning engineering. A lower training loss is meaningless if the training problem does not match the task you actually care about.

Shape checkpoint

If x=(B,T,C) and one head has width D, then Q, K and V are (B,T,D), scores are (B,T,T), weights are (B,T,T), and the output is (B,T,D).

Attention is not “the model looking at words.” It is a learned, differentiable routing operation over vectors.

Next: one head becomes many

One head gives the model one projected view of the sequence. Multi-head attention runs several such views in parallel and gives the network a richer set of routing patterns.
