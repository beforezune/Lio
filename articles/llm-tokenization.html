Before an LLM understands text, it has to break text into pieces.

A language model does not receive the sentence “the moon is bright.” It receives integers such as 184, 91, 37, 512.

Lio Learning Path · Beginner

Why tokens exist

Neural networks operate on numbers. Text is symbolic, variable-length and enormous, so an LLM needs a finite vocabulary and a deterministic way to map text into vocabulary IDs. That mapping is tokenization.

A token might be a whole word, part of a word, punctuation, whitespace, or another common byte sequence. Modern subword tokenizers balance vocabulary size against sequence length: too few vocabulary entries create long sequences; too many make the vocabulary expensive and rare words awkward.

A toy tokenizer

To understand the idea, start with characters. It is inefficient, but wonderfully transparent.

text = "hello world"
vocab = sorted(set(text))
encode = {ch: i for i, ch in enumerate(vocab)}
decode = {i: ch for ch, i in encode.items()}

ids = [encode[ch] for ch in text]
print(ids)
print("".join(decode[i] for i in ids))

The important invariant is that encoding followed by decoding returns the original text. A production tokenizer is more sophisticated, but it still creates a sequence of discrete IDs.

Why subwords are useful

Suppose a vocabulary contains play and ing. The model can represent playing as two tokens instead of requiring a separate vocabulary entry for every inflected word. This gives the model reusable pieces.

"playing" → ["play", "ing"]
"played"  → ["play", "ed"]

Actual tokenizers use algorithms such as byte-pair encoding or related schemes, and their exact behavior depends on the tokenizer vocabulary. The conceptual lesson is enough for our tiny model: tokens are the model's alphabet.

Vocabulary size is a trade-off

Let the vocabulary size be V and the context length be T. The model ultimately predicts a score for each of V possible next tokens at each of T positions. A larger vocabulary can shorten sequences, but the output layer and embedding table become larger.

For a teaching model, a character vocabulary might contain only a few dozen symbols. For a practical subword model, V can be tens of thousands or more.

Special tokens

Real systems often reserve IDs for structural markers such as beginning-of-sequence, end-of-sequence, padding, or other control symbols. These are not magical neural concepts; they are conventions in the token stream.

Turn a text file into training examples

data = torch.tensor(ids, dtype=torch.long)

# Example sequence:
# input  = [10, 20, 30, 40]
# target = [20, 30, 40, 50]

x = data[i:i+block_size]
y = data[i+1:i+block_size+1]

The one-position shift is the heart of next-token prediction. The model sees the prefix in x and is asked to predict the corresponding next token in y.

Learning checkpoint

If you can explain why the target sequence is shifted by one position, you understand the training objective at the data level.

A subtle limitation

Tokenization is not meaning. The IDs have no useful semantic geometry before training. Token 417 is not inherently “happy” or “database.” Meaningful structure is learned later through embeddings and the Transformer.

Tokens are the alphabet. The model learns what relationships between those symbols are useful.
