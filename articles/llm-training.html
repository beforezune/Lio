LLM FROM SCRATCH · 07 · TRAINING · 25 MIN READ

Training an LLM is a loop of tiny corrections repeated an enormous number of times.

The model predicts. A loss measures the mistake. Backpropagation computes how the parameters contributed to that mistake. An optimizer nudges the parameters. Then the next batch arrives.

Lio Learning Path · Intermediate
Learning goal

Trace one batch through logits, cross-entropy, gradients and AdamW, then learn how to read train/validation curves and diagnose unstable training.

Training starts with a prediction

Our batch contains input tokens x and the same text shifted one position for targets y. The model produces logits:

logits = model(x)
# shape: (B, T, V)

At every position, there is one score for each of the V vocabulary items. The correct next token is only one of those classes.

Cross-entropy turns predictions into a number

We want high probability on the correct target. Cross-entropy measures the negative log probability assigned to that target. PyTorch accepts logits directly:

loss = F.cross_entropy(
    logits.reshape(-1, vocab_size),
    targets.reshape(-1)
)

The reshape turns (B,T,V) into (B*T,V). Each token position becomes one classification example.

A useful intuition is: if the correct token receives probability 0.9, its contribution to loss is small; if it receives probability 0.001, its contribution is large.

The forward pass is not learning yet

This distinction is easy to miss. Running the model produces predictions. Learning happens only after the loss is connected back to the parameters and the optimizer updates them.

logits = model(x)
loss = F.cross_entropy(logits.view(-1,V), y.view(-1))

print(loss.item())

Backpropagation is the chain rule at scale

Every parameter influences the loss through a long chain of operations: embeddings affect hidden states, hidden states affect attention, attention affects logits, logits affect loss.

Automatic differentiation applies the chain rule through that computation graph and stores a gradient for each parameter.

optimizer.zero_grad(set_to_none=True)
loss.backward()

For a parameter w, its gradient approximates how the loss changes if w changes slightly. The optimizer uses these gradients to decide the next update.

Then the optimizer moves the weights

optimizer.step()

For a simple gradient descent update, you can imagine:

w ← w - learning_rate × gradient

Real training commonly uses adaptive optimizers. Adam maintains running estimates related to the first and second moments of gradients. AdamW decouples weight decay from the adaptive gradient update.

optimizer = torch.optim.AdamW(
    model.parameters(),
    lr=3e-4,
    weight_decay=0.1,
)

The exact values are experimental choices. A learning rate that works for one architecture and dataset can fail for another.

The minimal loop

for step in range(max_steps):
    xb, yb = get_batch("train")

    logits = model(xb)
    loss = F.cross_entropy(
        logits.reshape(-1, vocab_size),
        yb.reshape(-1)
    )

    optimizer.zero_grad(set_to_none=True)
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()

    if step % 100 == 0:
        print(step, loss.item())

Why zeroing gradients matters

PyTorch accumulates gradients by default. If you forget to clear them, gradients from multiple batches add together. Sometimes gradient accumulation is intentional, but accidental accumulation changes the effective update and can destabilize learning.

Training loss versus validation loss

A model can become better at reproducing its training examples without becoming better at unseen text. Keep a validation split and periodically measure it without updating parameters.

@torch.no_grad()
def estimate_loss():
    model.eval()
    # sample several batches from train and validation
    # average their losses
    model.train()

If training loss falls and validation loss falls too, the model is generally improving under the measured objective. If training keeps falling while validation stalls or rises, overfitting is one possible explanation.

Perplexity

Perplexity is commonly related to the exponential of average negative log-likelihood. Lower is better when comparing the same evaluation setup and tokenization. It is useful for language-model evaluation, but it does not summarize every capability people care about.

Learning-rate schedules

Optimization can benefit from changing the learning rate over time. Warmup can prevent overly aggressive early updates; decay can allow finer adjustments later.

# Conceptual schedule
learning_rate: small → warmup → peak → gradual decay

Do not copy a schedule because a large model used it. Measure the curve on your own model.

Gradient clipping

Sometimes gradients become very large. Clipping limits their norm:

torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)

Clipping is a safety mechanism, not a diagnosis. If training repeatedly explodes, inspect the learning rate, data, initialization, normalization and implementation.

What a healthy experiment looks like

Do not record only the final loss. Save checkpoints, training loss, validation loss, learning rate and generation samples. A curve tells you when something changed; samples help tell you what changed.

For a tiny character model, generated text may become more structured before it becomes impressive. Repetition, punctuation patterns and common word fragments can appear as the model learns the distribution.

A powerful debugging trick

Try to overfit a tiny batch. If the model cannot drive the loss down on a very small fixed dataset, suspect an implementation bug before blaming the dataset or model capacity.

This is one of the most useful habits in deep-learning engineering: make the problem smaller until success should be easy.

Checkpoint

Say the entire loop aloud: token batch → logits → cross-entropy → scalar loss → backward pass → gradients → optimizer step → updated parameters. If you can explain what changes at each arrow, training is no longer a black box.

The model does not wake up and suddenly understand language. Optimization keeps making small parameter changes until useful statistical structure becomes easier to predict.
